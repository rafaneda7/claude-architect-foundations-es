## Glosario y consulta técnica

El [glosario CCAR-F](GLOSARIO_D1_D5.md) organiza los conceptos por dominio, con definiciones, aplicaciones y recomendaciones para interpretar escenarios de arquitectura.

| Sección | Para qué sirve |
|---|---|
| [D1 — Agentic Architecture & Orchestration](GLOSARIO_D1_D5.md#d1--agentic-architecture--orchestration) | Distinguir agentes, workflows, patrones de coordinación y mecanismos de control. |
| [D2 — Tool Design & MCP Integration](GLOSARIO_D1_D5.md#d2--tool-design--mcp-integration) | Diseñar herramientas y comprender clientes, servidores, transportes y contratos MCP. |
| [D3 — Claude Code Configuration & Workflows](GLOSARIO_D1_D5.md#d3--claude-code-configuration--workflows) | Consultar `Glob`, `Grep`, `Read`, `Edit`, `Write`, `Bash`, configuración, permisos, hooks y skills. |
| [D4 — Prompt Engineering & Structured Output](GLOSARIO_D1_D5.md#d4--prompt-engineering--structured-output) | Precisar técnicas de prompting, esquemas, validación estructural y evaluación. |
| [D5 — Context Management & Reliability](GLOSARIO_D1_D5.md#d5--context-management--reliability) | Revisar contexto, RAG, memoria, fiabilidad, seguridad y observabilidad. |
| [Matriz de distinciones conceptuales](GLOSARIO_D1_D5.md#matriz-de-distinciones-conceptuales) | Comparar **114 pares o grupos de términos** y evitar confusiones habituales. |
| [Casos de aplicación](GLOSARIO_D1_D5.md#casos-de-aplicación) | Aplicar criterios técnicos a situaciones semejantes a las de una evaluación. |
| [Guía de referencia y repaso](GLOSARIO_D1_D5.md#guía-de-referencia-y-repaso) | Consultar patrones, herramientas, comandos, contratos y secuencias de diagnóstico. |
| [Referencias técnicas](GLOSARIO_D1_D5.md#referencias-técnicas) | Acceder a documentación oficial y comprobar compatibilidades de versión. |

## Método de estudio

1. Leer la guía de cada jornada y utilizar el glosario para aclarar términos.
2. Completar las prácticas sin consultar inicialmente los solucionarios.
3. Ejecutar las pruebas correspondientes y analizar los errores.
4. Resolver el checkpoint o la evaluación del día, justificando las decisiones técnicas.
5. Repasar la matriz de distinciones y la guía de referencia antes de los simulacros.

Las prácticas que realizan llamadas a la API pueden consumir créditos; las pruebas locales no requieren una clave de Anthropic salvo que la guía del ejercicio indique expresamente lo contrario.

## Evaluación final

El [Día 8](../Checkpoints/Dia_8_Simulacro/) incluye un simulacro de **60 preguntas** con una duración de **120 minutos**, en formato interactivo y Markdown. Los resultados son indicadores de aprendizaje de este repositorio y no constituyen una predicción de la nota oficial.
